# Hafez | حفيظ

منصّة تنسيق فائض الطعام بين قاعات المناسبات والجمعيات والمستفيدين — **نموذج عرض (هاكاثون MVP) ببيانات تجريبية محلية فقط**.

> ⚠️ **نموذج عرض وليس نظامًا للإنتاج.** لا يوجد خادم ولا قاعدة بيانات ولا تسجيل دخول حقيقي. تبديل الحسابات يشرح الصلاحيات بصريًا فقط، وفحوص الصلاحية في المتصفح **ليست حماية أمنية**.

## ما المُنفَّذ في هذا الإصدار

| الدور / الشاشات                                                                                                                                 | Figma               | الحالة                                                                  |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- | ----------------------------------------------------------------------- |
| A2 — اختيار حساب تجريبي                                                                                                                         | `15:564` · `15:650` | ✅ مُنفَّذة                                                             |

| D — منسق الجمعية: D1 الفرص، D2 التفاصيل، D3 الاعتذار، D4 تعيين الممثل، D5 التسليمات، D6 الإعلانات والطلبات، D7 بلاغات المستفيدين، المهام، السجل | D1–D7               | ✅ مُنفَّذة                                                             |

كل الأدوار تعمل على **سجل بيانات واحد**: ما تسجله القاعة يظهر للجمعية، وإسناد الجمعية يظهر في مهام الممثل، وتأكيد الممثل والجمعية يحدّث حالة المناسبة لدى القاعة، والإعلان المنشور من تسليم موثق يظهر للمستفيد، وتأكيد المستفيد يحدّث النقاط والأثر لدى الجمعية. اختبار `tests/e2e/journey.spec.ts` يمرّ بهذه الرحلة كاملة عبر الواجهة: **C2 → C3 → D2 → D4 → E2 → E3 → E4 → D5 → C → D6 → H2 → D6 → H7**، بالعربية (RTL، الافتراضية) والإنجليزية (LTR)، على الجوال والحاسوب.

## التشغيل

المتطلبات: Node.js ‏20.9 أو أحدث (جُرِّب على Node 24.16).

```bash
npm install
```

```bash
npm run dev
```

ثم افتح <http://localhost:3000> (يُحوَّل تلقائيًا إلى `/ar`).

نسخة الإنتاج:

```bash
npm run build
```

```bash
npm run start
```

## الفحوص والاختبارات

| الأمر                  | ما يفعله                                                                   |
| ---------------------- | -------------------------------------------------------------------------- |
| `npm run typecheck`    | فحص TypeScript (strict)                                                    |
| `npm run lint`         | ESLint (قواعد Next.js + TypeScript)                                        |
| `npm run format:check` | Prettier                                                                   |
| `npm test`             | اختبارات الوحدة (Vitest)                                                   |
| `npm run test:e2e`     | اختبارات الواجهة (Playwright) على نسخة الإنتاج، بحجمي حاسوب 1440 وجوال 390 |
| `npm run check`        | typecheck + lint + test                                                    |

اختبارات Playwright تستخدم **Microsoft Edge المثبّت في Windows** (`channel: "msedge"`) فلا تحتاج تنزيل متصفح. لاستخدام Chrome:

```bash
set PW_CHANNEL=chrome&& npm run test:e2e
```

كل اختبار E2E يفشل تلقائيًا إذا ظهر أي خطأ في Console أو استثناء غير مُعالَج في الصفحة.

## إعادة تعيين بيانات العرض

البيانات التجريبية محفوظة في `localStorage` المتصفح تحت مفتاحين فقط:

- `hafez.demo.data.v1` — بيانات العرض (القاعات، المناسبات، السجل…)
- `hafez.demo.session.v1` — الحساب التجريبي المختار

طرق إعادة التعيين:

1. **من الواجهة:** إذا تلفت البيانات تظهر شاشة «تعذّر قراءة بيانات العرض» مع زر **«إعادة تعيين بيانات العرض»**.
2. **يدويًا:** أدوات المطوّر ← Application ← Local Storage ← احذف المفتاحين أعلاه ثم أعد تحميل الصفحة. (تُنشأ البيانات الأولية من جديد تلقائيًا.)
3. **من Console:**
   ```js
   localStorage.removeItem("hafez.demo.data.v1");
   localStorage.removeItem("hafez.demo.session.v1");
   location.reload();
   ```

رفع `DEMO_CONFIG.dataVersion` في `src/config/demo.ts` يجعل كل المتصفحات تعيد تحميل البيانات الأولية تلقائيًا.

## بنية المشروع

```
src/
  app/[locale]/          المسارات (A2 في page.tsx، hall/ charity/ field/ beneficiary/، صفحة «قيد التطوير» للمشرف والحكّام، 404)
  components/ui/         مكوّنات نظام التصميم (Button, StatusBadge, MetricCard, …)
  components/layout/     شريط العرض، الشريط الجانبي، مبدّل الحساب واللغة، بوابة مساحة العمل
  features/              شاشات كل دور (account-picker, hall, charity, field, beneficiary, common)
  domain/                الأنواع، الأدوار، الصلاحيات can()، المحدِّدات، وأوامر سير العمل (domain/workflow)
  data/                  البيانات الأولية، مخطط zod، Repository، متجر Zustand
  config/demo.ts         قيم تشغيلية مؤقتة (غير نهائية) في مكان واحد
  i18n/ , messages/      next-intl + نصوص العربية والإنجليزية
tests/unit, tests/e2e    Vitest و Playwright
brand/ , docs/           الأصول والوثائق الأصلية — لم تُعدَّل
```
