# Hafez | حفيظ

**حفيظ يربط فائض طعام المناسبات بمن يحتاجه — من توقع الكمية قبل التجهيز، إلى إنقاذ ما فاض بتوثيق، إلى وصوله للمستفيد بتأكيده — وكل رقم أثر محسوب من سجلات حقيقية لا من تقديرات.**

🔗 **الديمو الحي:** <https://hafez-omega.vercel.app/ar/journey> — صفحة واحدة تمر بالرحلة كاملة ولوحة الأثر.

> ⚠️ **نموذج أولي للهاكاثون ببيانات تجريبية وهمية.** لا يوجد خادم ولا قاعدة بيانات ولا تسجيل دخول حقيقي بعد؛ البيانات تُحفظ في متصفح كل زائر، وفحوص الصلاحية في المتصفح للشرح وليست حماية أمنية.

---

## المشكلة

في المناسبات (أفراح، ولائم، حفلات) يُجهَّز طعام أكثر من الحاجة بسبب الفجوة بين الحضور المتوقع والفعلي، وما يفيض يتلف خلال ساعات لأنه لا توجد قناة سريعة وموثوقة توصله لمن يحتاجه. وحتى حين يُنقل، لا يُعرف كم أُنقذ فعلًا وكم وصل للمستفيدين.

## الحل

منصة واحدة تجمع أربعة أطراف على **سجل واحد** لكل مناسبة:

| الطرف               | دوره في حفيظ                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------- |
| **مسؤول القاعة**    | يسجّل المناسبة، ويحصل على توصية بالكمية المناسبة قبل التجهيز، ثم يتيح الفائض للتنسيق      |
| **منسق الجمعية**    | يقبل الفرصة ويسند ممثلًا من فريقه، ويوثّق الاستلام، وينشر الطعام للمستفيدين ويقبل طلباتهم |
| **الممثل الميداني** | يسجّل الوصول، ويعاين بقائمة سلامة، ويسجّل الوزن الفعلي عند التسليم                        |
| **المستفيد**        | يطلب ضمن حد عادل، ويؤكد الاستلام، ويبلّغ عن فائض لديه، ويبني سلوكًا عبر درع ونقاط         |

ويتابع **مدير المنصة** الصورة كاملة: الأثر، وحالات المناسبات، وسجل من نفّذ ماذا ومتى.

## الرحلة في ست خطوات

1. **القاعة تسجّل وتتوقع:** 300 ضيف و210 كجم مخططة ← التوقع يوصي بـ180 كجم قبل النشر (تقليل الهدر يبدأ من التجهيز).
2. **الجمعية تقبل وتسند ممثلًا** من فريقها في وقت الجاهزية.
3. **الممثل يعاين ويسلّم:** قائمة سلامة، ثم تسليم مبدئي بالوزن الفعلي — لا تُفترض السلامة من العدد.
4. **الجمعية توثّق الاستلام وتنشر:** تُعبّأ الكمية الموثقة فقط في إعلان للمستفيدين بمنطقة عامة (بلا عناوين دقيقة).
5. **المستفيد يطلب ويؤكد الاستلام:** عندها فقط تُحتسب الكمية «وصلت للمستفيدين».
6. **من الوعي إلى السلوك:** نصيحة اليوم وتعهد أسبوعي، ونقاط من أحداث موثقة فقط — لا نقاط لمجرد الإرسال أو القراءة.

## كيف نقيس الأثر

لوحة الأثر في صفحة الرحلة تفصل التقدير عن الموثّق دائمًا:

| المؤشر                   | كيف يُحسب                                                     | نوعه  |
| ------------------------ | ------------------------------------------------------------- | ----- |
| هدر تجنّبناه قبل التجهيز | الفرق بين الكمية المخططة والموصى بها عند اعتماد القاعة للتوقع | تقدير |
| طعام أُنقذ بتوثيق        | تسليمات أكّدتها الجمعية + بلاغات أسر وُثّق إنقاذها            | موثّق |
| وصل للمستفيدين           | طلبات أكّد المستفيد استلامها فقط                              | موثّق |
| سلوك مستدام              | استلامات مؤكدة وتعهدات أسبوعية                                | موثّق |

ومعها رسم لتطور الأثر يومًا بيوم، ومسار الكمية من التقدير قبل المناسبة إلى ما وصل فعلًا.

## ما يميّز حفيظ

- **سجل واحد لكل الأطراف:** ما تسجله القاعة تراه الجمعية، وما يوثّقه الممثل يحدّث حالة المناسبة لدى الجميع.
- **منع الهدر قبل حدوثه** بالتوقع، لا إنقاذه بعده فقط.
- **أثر صادق:** لا يُحتسب شيء «منقذًا» قبل توثيقه، ولا «موزعًا» قبل تأكيد المستفيد.
- **كرامة المستفيد وخصوصيته:** رمز مستعار، ومنطقة عامة فقط، وحد عادل لكل طلب.

## الخطوة التالية

- قاعدة بيانات وخادم بدل الحفظ في المتصفح، وتسجيل دخول حقيقي، ونقل الصلاحيات إلى الخادم.
- إشعارات (SMS/واتساب) ورفع صور البلاغات.
- معايرة التوقع وقيم النقاط ببيانات تجربة فعلية.

منطق العمل (القواعد، التحقق، الصلاحيات، أوامر سير العمل) مكتوب كطبقة مستقلة عن الواجهات، والوصول للبيانات يمر عبر طبقة واحدة (`Repository`)؛ لذلك يمكن ربطها بقاعدة بيانات لاحقًا دون إعادة بناء الشاشات.

## للمطوّرين

### التشغيل

المتطلبات: Node.js ‏20.9 أو أحدث (جُرِّب على Node 24.16).

```bash
npm install
```

```bash
npm run dev
```

ثم افتح <http://localhost:3000/ar/journey>.

نسخة الإنتاج:

```bash
npm run build
```

```bash
npm run start
```

### الفحوص والاختبارات

| الأمر                  | ما يفعله                                                                   |
| ---------------------- | -------------------------------------------------------------------------- |
| `npm run typecheck`    | فحص TypeScript (strict)                                                    |
| `npm run lint`         | ESLint (قواعد Next.js + TypeScript)                                        |
| `npm run format:check` | Prettier                                                                   |
| `npm test`             | اختبارات الوحدة (Vitest)                                                   |
| `npm run test:e2e`     | اختبارات الواجهة (Playwright) على نسخة الإنتاج، بحجمي حاسوب 1440 وجوال 390 |
| `npm run check`        | typecheck + lint + test                                                    |

آخر نتيجة: **82 اختبار وحدة** و**111 اختبار واجهة** ناجحة (3 متخطاة عمدًا لأنها خاصة بحجم شاشة واحد). من بينها اختبار يمرّ برحلة كاملة عبر الواجهات: إنشاء مناسبة ← إسناد ← معاينة وتسليم ← توثيق ونشر ← طلب المستفيد وتأكيده.

اختبارات Playwright تستخدم **Microsoft Edge المثبّت في Windows** (`channel: "msedge"`) فلا تحتاج تنزيل متصفح. لاستخدام Chrome:

```bash
set PW_CHANNEL=chrome&& npm run test:e2e
```

كل اختبار E2E يفشل تلقائيًا إذا ظهر أي خطأ في Console أو استثناء غير مُعالَج في الصفحة.

### إعادة تعيين بيانات العرض

البيانات التجريبية محفوظة في `localStorage` المتصفح تحت مفتاحين:

- `hafez.demo.data.v1` — بيانات العرض (القاعات، المناسبات، السجل…)
- `hafez.demo.session.v1` — الحساب التجريبي المختار

طرق إعادة التعيين:

1. **من صفحة الرحلة:** زر «إعادة ضبط العرض».
2. **عند تلف البيانات:** تظهر شاشة «تعذّر قراءة بيانات العرض» مع زر **«إعادة تعيين بيانات العرض»**.
3. **من Console:**
   ```js
   localStorage.removeItem("hafez.demo.data.v1");
   localStorage.removeItem("hafez.demo.session.v1");
   location.reload();
   ```

رفع `DEMO_CONFIG.dataVersion` في `src/config/demo.ts` يجعل كل المتصفحات تعيد تحميل البيانات الأولية تلقائيًا.

### بنية المشروع

```
src/
  app/[locale]/          المسارات (اختيار الحساب، journey/، hall/ charity/ field/ beneficiary/، 404)
  components/ui/         مكوّنات نظام التصميم (Button, StatusBadge, MetricCard, …)
  components/layout/     شريط العرض، الشريط الجانبي، مبدّل الحساب واللغة، بوابة مساحة العمل
  features/              شاشات كل دور (hall, charity, field, beneficiary) + journey (صفحة الرحلة ولوحة الأثر)
  domain/                الأنواع، الأدوار، الصلاحيات can()، المحدِّدات، وأوامر سير العمل (domain/workflow)
  data/                  البيانات الأولية، مخطط zod، Repository، متجر Zustand
  config/demo.ts         قيم تشغيلية مؤقتة (غير نهائية) في مكان واحد
  i18n/ , messages/      next-intl + نصوص العربية والإنجليزية
tests/unit, tests/e2e    Vitest و Playwright
brand/ , docs/           الأصول والوثائق الأصلية — لم تُعدَّل
```
